# 角色动画探针与自制精灵皮肤

## 已核对的进度条头像

用户所说“像素头像”已通过 2026-10-12 真机记录定位到操作倒计时进度条。

- 实际控件为 UI.UIOperationTime_Progress.loader_Head；路径在 OperateTimeWindow 中。
- GameLogic.OperationTimer.ActionDownTime → BattlePlayerData.GetCharacterHeadUrl → CharacterHandle.CharacterMap → OperateTimeWindow.UpdateOperationProgress。
- 小地图的 UI.UIBattleInfo_Com_MiniMap_Icon 也使用 CharacterMap，但它是另一个控件；0.1.1 起分别记录 progressAvatar 和 mapAvatar。
- 本地 Character.bin 中，角色 114 的 CharacterMap = `UT_AccountHeadShot_70914`；角色 101 为 `UT_AccountHeadShot_70901`。
- 这些图片虽然命名为 AccountHeadShot，进度条选择哪一张是按角色配置决定，并不直接跟随玩家的账号头像装扮。
- 玩家账号头像另走 RoomPlayer.HeadURL → Fashion 装扮槽位 1 → Item.SubMeterID → Fashion.AccountHeadShotDict → GetHeadShot。
- 局内玩家角色头像 ProfilePhoto、完整立绘 Character、HUD InGameCharacter 也都是独立入口。

进度条头像是一张静态图片，未来角色皮肤清单必须包含 CharacterMap。若用全局图片地址覆盖，同地址的账号头像等其他位置也会一起变化；需要限定作用域时，按进度条控件单独应用。

## 探针行为

新增临时研究模组 `CharacterProbeMod`，不加入正式内置模组发布清单。模组默认在启动 30 秒后初始化，只读取游戏/Unity 对象并写自己的采集目录，不发送操作、不设置动画参数、不改皮肤配置、不替换贴图、不读取纹理像素。

输出位置：

```text
<游戏目录>/AstralParty_ModLoader/mods/CharacterProbeMod/captures/<UTC ticks>/
  observations.jsonl
  status.json
```

每次启动独立目录。OnLateUpdate 观察活跃 CharacterAnimator 上的 SpriteRenderer，记录精灵变化；每两秒扫描一次人物和可见 UI，并刷新状态、缓冲写盘。只在元数据或状态首次出现/变化时记录相应信息。

记录内容：

- 会话、Unity 版本、场景。
- 对局角色、原皮肤物品 ID、CharacterLabel、CharacterMap、ProfilePhoto、HUD、立绘、缩略图、准备图、Bust、账号头像地址。
- 进度条头像的实际 URL、UI 路径和位置。
- 所有可见 UT_Hero / UT_AccountHeadShot / UT_Platform 图片的路径、父控件类型和尺寸。
- 人物实例 ID、层级路径、控制器、缩放。
- 控制器剪辑名、时长、帧率、循环属性，以及可读取的动画事件。
- 实际精灵帧变化、原精灵 ID、翻转。
- 每个精灵的 rect、pivot、PPU、图集名称、图集尺寸、纹理 ID，以及可读取的 textureRect。
- 基础动画层的状态/剪辑切换：每六个渲染帧查询一次；状态信息不保证包含短于采样间隔的过渡。
- 兼容性异常。可选反射读取失败时继续采集其他信息，异常去重；写盘失败时停掉探针，避免持续刷屏。

上限：待写缓冲约 256K 字符、每次启动约 32M 字符。0.1.2 起待写缓冲将满时立即写盘，再接收新行；只在总容量超限或单条记录超过缓冲大小时记录 dropped。字节大小可能因 UTF-8 非 ASCII 内容大于字符数。没有使用 FileStream、FileInfo、StreamReader/Writer、Flush(bool)、P/Invoke 等已知热更兼容陷阱。

2026-10-12 的 13:56:50 会话（0.1.1）已完成一次回放并返回大厅：保存 66,263 条记录、831 条不同精灵元数据、101 段剪辑，探针异常为 0；但短时缓冲溢出丢弃 6,444 条记录，至少 17 个已记录精灵引用没有对应元数据。该采集可用于确认加载链，不能当成完整帧清单；0.1.2 的突发写入回归验证通过，修订后的真机丢弃情况仍待下一次采集核对。

本地没有 UnityEngine.AnimationModule 的参考 DLL，因此动画器、剪辑、事件和状态读取使用缓存反射。0.1.1 的 getter/基类/字段回退已在真机采到控制器、剪辑与状态信息，最新会话无探针异常。UI Playables 可能没有 AnimatorController，仍采集其精灵变化；其原始剪辑时序可随后从资源包核对。

## 用户采集步骤

1. 完全退出游戏后重新启动，保证新模组被发现；探针安装不会自动注入已运行的游戏。
2. 进入大厅后等启动约 30 秒，再打开目标角色的皮肤/选人界面，并停留数秒。
3. 使用以后准备制作皮肤的角色及原皮肤打一局。正常经历走路、待机和战斗即可；有机会的话使用角色技能。
4. 结算后在界面停留至少五秒，让最后一批记录写盘，再退出游戏。
5. 告诉研究者“打完了”，直接读取本机采集目录，无需上传文件。

一局只反映出现过的动作和实际渲染到的帧，不能当成全部动画资源清单。帧率不足、加速、两秒扫描前创建销毁的短演出，都可能导致漏采；精确动画时间与完整帧列表必须随后读取源资源包。进度条 UI 位置和资源地址可以在本次记录中核对。

## 构建与验证

```powershell
dotnet build mods/CharacterProbeMod/CharacterProbeMod.csproj -c Release
dotnet run --project tests/CharacterProbeMod.Smoke/CharacterProbeMod.Smoke.csproj -c Release
```

离线冒烟覆盖 JSON 控制字符/路径转义、UTC ticks 整数精度、非有限浮点数、小数逗号区域、增量缓冲写入、待写容量限制和热更 BCL 源码检查。这不代替游戏真机验证。

部署仅复制探针自己的 DLL、PDB、JSON 到 `mods/CharacterProbeMod/`；不覆盖 SDK、version.dll 或玩家其他模组配置。关闭游戏后移走这个模组 DLL 即停止下次采集，captures 可以留着分析。

采集后摘要：

```powershell
python tools/summarize-character-probe.py --output <工作区报告路径>.json
```

默认分析当前国服安装位置的最新采集，也可把采集目录作为第一个参数。解析器会报告尚未写完/无效的行、探针错误、丢弃计数、角色与皮肤、进度条 URL、剪辑和图集摘要。

## 自制二维精灵动画制作方式

推荐先做“保留原动作、替换渲染帧”的模组，而不是第一步就重写 AnimatorController。

1. 从目标角色/原皮肤的资源导出动作与帧清单、原帧图、pivot 和 PPU，建立参照模板。进度条头像单独制作静态 PNG。
2. 用 Aseprite、绘图软件或其他工具制作透明底动画，先完成 Idle、Walk、Walk-Back，之后补齐受击、死亡、战斗与技能相关动作。
3. 自制包优先使用“每帧 PNG + 清单”，清单说明所属角色/原皮肤、对应原精灵、脚底 pivot、PPU；也可用 spritesheet + rect 清单。
4. 未来 CharacterSkinMod 读取 PNG → Texture2D → Sprite，在原动画更新后的 LateUpdate 将目标渲染器当前原帧映射成自制 Sprite。游戏保持自己的 Animator、状态机、时间和事件。
5. 图片加载和 Sprite.Create 等 API 要先在目标游戏验证。当前探针只读取数据，不执行这段替换。
6. 清单必须按角色/皮肤及资源身份区分，不能全局仅按 Walk_00000 等通用名字匹配。缺帧回退原图；开关关闭或对象销毁时恢复并释放自制资源。
7. 地图人物、房间预览和其他 UI 像素动画均要覆盖；动画后期还有特殊 Timeline 演出需要进一步验证。

不要简单把新人物画进原图集任意位置。原帧可能有紧密网格、裁切和图集排列；新轮廓超出原网格会被裁切。创建独立 Sprite 能更自由地调整轮廓，同时保持正确的脚底 pivot 与 PPU。

更高级的路线是使用 Unity 2021.3.45f2 和 Windows 构建目标制作 AssetBundle，包含自制 Sprite/AnimationClip/控制器。随后由托管模组调用 AssetBundle 加载，替换相应动画资源。这一路线必须验证本游戏 AssetBundle API 的 AOT 可用性，并保持原状态名、参数、事件、层级路径和 Timeline 兼容；不能把普通 Unity 编辑器项目产物当作现成可用的游戏皮肤。

当前交付是只读采集探针，不是已经能安装自制动画包的角色换肤模组。采集结束后才据实际目标角色数据确定帧清单与加载实现。
