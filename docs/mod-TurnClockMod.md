# mod-回合时钟 (TurnClockMod)

> 变速时**只把你自己的操作倒计时按真实时间走**：2 倍速下 30 秒的回合窗口仍然是 30 秒真实时间，
> 而动画、战斗表演、其他玩家回合与 PVE 怪物回合照常加速。

## 为什么需要它

变速改的是引擎感知的时间 —— 游戏里只有一个时钟，所以你自己那个 30 秒的操作倒计时也会跟着快 2 倍，
**15 秒墙钟就走完**。到点后客户端会替你把动作发出去：

- 商店超时 = 空手买一次（什么都不买）；
- 出牌超时 = 自动过牌 / 自动掷骰；
- 连续超时还会被记为挂机，达到上限直接判负退出。

这个 mod 不碰全局时间，只每帧把**你自己的计时器进度**拨回"按真实时间该走到的位置"，于是：

| 对象 | 变速时的行为 |
| --- | --- |
| 我的操作窗口（掷骰、选方向、商店、事件、筹码、战斗出牌/防御、投票、选轮次卡…） | 按真实时间走，30 秒就是 30 秒 |
| 其他玩家的回合倒计时显示 | 按真实时间显示（`otherPlayers` 可关） |
| 动画、战斗表演、其他玩家回合、PVE 怪物回合 | 保持你设置的倍率 |
| 倍率为 1.0x | 完全不介入 |

## 配置

`mods\TurnClockMod\config.json`（首次运行自动生成，保存后约 1 秒热重载）：

```json
{
  "enabled": true,
  "otherPlayers": true,
  "dryRun": false,
  "logWindow": true,
  "speedRefreshSeconds": 0.2,
  "elapsedMember": "",
  "startMember": "",
  "clockMember": "",
  "durationMember": "duration"
}
```

| 键 | 说明 |
| --- | --- |
| `enabled` | 总开关。关闭后不读取任何计时器，也不写任何字段 |
| `otherPlayers` | 其他玩家回合的倒计时显示也按真实时间走（默认开启）。关掉只处理你自己的操作窗口 |
| `dryRun` | 只跟踪、只记录，不改计时器（排查用） |
| `logWindow` | 每个操作窗口结束打一行日志（默认开启），见下面「日志怎么看」 |
| `speedRefreshSeconds` | 读取当前倍率的间隔（秒），默认 `0.2` |
| `elapsedMember` | 手动指定"已用时长"字段（只对把 elapsed 存成字段的计时器有意义）；留空 = 自动探测 |
| `startMember` | 手动指定"起点"字段（默认自动找 `_startTime`）；一般不用改 |
| `clockMember` | 手动指定"每帧刷新的时钟"字段（默认自动找 `_lastUpdateTime`）；一般不用改 |
| `durationMember` | 总时长成员名，用于把写回值夹在终点之前；找不到不影响补偿 |

与 [变速](mod-SpeedHackMod.md) 独立：倍率仍由那边用热键调，这个 mod 只负责"我的倒计时用真实时间"。

## 原理

游戏用的 Unity Timer 并不保存"已用时长"字段，而是每帧算 `已用时长 = 时钟 − 起点`：

```
_startTime = 72.007      ← 起点(游戏时间)
_lastUpdateTime = 72.007 ← 每帧刷新的时钟
duration = 30
```

所以 2 倍速下 `时钟` 走得快一倍，倒计时自然 15 秒就烧完。这个 mod 每帧把**起点按同样的比例往后推**——

```
delta = 时钟这一帧推进了多少(游戏秒)
push  = delta − delta / 倍率
_startTime += push        →  已用时长这一帧只涨 delta / 倍率
```

计数基准取"时钟"而不是真实时间：计时器暂停（时钟不涨）时什么都不做，恢复后从原处继续。

如果某版游戏把 elapsed 换成了真正的字段，会自动走"直接回退 elapsed"的另一条路。

## 切倍率 / 关掉变速时

补偿是**逐帧、无记忆**的：每帧只比较「计时器时钟这一帧走了多少」和「当前倍率」，不依赖历史倍率，也不预测未来。所以：

- 切到 `1.0x`：立刻停止写入，倒计时从当前剩余时间继续按真实时间走；
- 从 `1.0x` 切回 `2x`/`9x`：从当前剩余时间继续补偿，不跳变；
- 同一个窗口里反复加减：总时长不受倍率历史影响（离线用例里 1x/9x 每 0.3 秒来回切，结果仍是 30 秒）；
- 倍率停在 `1.0x` 或关掉本 mod：不写任何字段，也没有残留状态（计时器每次创建都会由游戏重设起点）。

唯一的延迟是"按热键 → mod 知道新倍率"：加载器每 100ms 检查一次请求文件，mod 平时每 `speedRefreshSeconds` 读一次状态。
mod 会用**实测**的时钟速率和缓存倍率对比，对不上就立刻重读，并且窗口打开时强制重读一次 ——
所以切换后最多差约一帧的补偿量（9x 时约 0.15 秒），不会累积。

## 日志怎么看

游戏日志（`AstralParty_ModLoader\logs\`）里，初始化时会打一行计时器成员清单，例如：

```
[TurnClockMod] 读取 timerDict 走通: IDictionary
[TurnClockMod] 计时器类型 UnityTimer.Timer 的 float 成员: duration=30, _startTime=72.007, _lastUpdateTime=72.007
[TurnClockMod] 补偿方式: 推后起点(_startTime) · 时钟(_lastUpdateTime) · 时长 duration
```

之后每个操作窗口结束打一行：

```
[TurnClockMod] 操作窗口结束: 计时器 30.0s / 墙钟 29.9s, 倍率 2.0x, 补偿 1786 次
```

两个数字接近就说明生效了；如果看到"计时器 30.0s / 墙钟 15.0s"或下面这种警告，说明这一版游戏换了计时器实现：

```
[TurnClockMod] 计时器推进快于真实时间(15.0s 游戏 / 7.5s 真实), 补偿可能没生效
```

此时功能会**自动停用**（只影响本 mod，不影响游戏本身），把那几行日志连同成员清单反馈即可。

## 注意

- 只在倍率 **> 1.0x** 时做补偿；1.0x 下不写任何字段。
- 只改本地计时器的进度，不发送任何协议包、不改服务器时间、不改变动作与结算逻辑。
- 找不到游戏计时器或成员时自动停用，只记录一行日志，不会让游戏崩溃。
