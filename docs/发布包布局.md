# 发布包布局

每个 `modloader-<版本>` Release 提供三类独立 ZIP；每类同时提供版本化名称与固定名称，共六个必需资产。

| 类别 | 版本包 | 固定名 | 内容 |
|---|---|---|---|
| 加载器 | `cesium-loader-<版本>.zip` | `cesium-loader.zip` | version.dll、Bootstrap、运行 SDK、内置 mods、配置、版权声明与 AGPL 许可全文及配套 PDB；不包含 skins |
| 默认皮肤 | `cesium-default-skins-<版本>.zip` | `cesium-default-skins.zip` | 仓库 dist/modloader/AstralParty_ModLoader/skins/default 中的全部文件 |
| SDK 工具 | `cesium-sdk-tools-<版本>.zip` | `cesium-sdk-tools.zip` | cesium CLI、开发 SDK、文档、示例 |

## 安装

加载器包解压到游戏 exe 所在目录。需要默认皮肤时，额外下载默认皮肤包并解压到同一目录，包内路径为：

```text
AstralParty_ModLoader/skins/default/
```

包内另附 `CesiumLoader-NOTICE.txt` 与 `CesiumLoader-LICENSE.txt`，在游戏 exe 目录与 `AstralParty_ModLoader` 各一份；安装或使用即表示同意 AGPL-3.0。

默认皮肤包不包含其他皮肤方案、加载器或模组。解压会覆盖 default 下的同名文件；修改过默认方案的玩家应先备份，或将自己的方案保存在其他目录。CardSkinMod 仍随加载器包提供；未提供皮肤的卡面使用游戏原图。

Toys 的现有加载器下载仍使用 cesium-loader.zip，不会自动安装默认皮肤。SDK 工具包供开发者使用。

## 发布流程

1. 本地构建并测试，运行 tools/package-modloader.ps1 生成三类六个 ZIP 并检查内容。该脚本从源码构建全部程序集，再用 tools/stage-modloader-dist.ps1 组装 dist 布局；`-SkipBuild` 复用上一次的构建结果。
2. 确认内容后提交，按现有流程打 modloader-<版本> tag 触发 Action。
3. CI 从源码构建原生加载器、Bootstrap、SDK、全部内置模组与 SDK CLI，运行测试，然后组装 dist 布局并分别打包加载器和 SDK 工具。
4. tools/package-default-skins.ps1 复制 default 方案到独立暂存目录、生成皮肤 ZIP，并校验六个资产及固定名/版本名的 SHA256 一致性。
5. Action 上传全部 cesium-*.zip；Release 发布前再次要求六个必需资产存在。

构建不需要任何本地提取目录：编译期引用的游戏程序集随仓库放在 refs/game/。dist/modloader/ 下的程序集是构建输出，不入库；入库的只有配置、模组 sidecar 与默认皮肤素材。

皮肤目录不存在、没有图片、ZIP 清单与源文件不一致、加载器包出现 skins、或 SDK/加载器包缺少关键文件时，构建失败，不发布残缺包。实验性的 AI 接管包继续默认关闭。
