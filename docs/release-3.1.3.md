# CesiumLoader 3.1.3

## 启动与主线程调度

启动阶段的等待与调度做了收敛，体感上主要体现在进入游戏与切换界面时：

- **共享就绪探测**：所有模组共享一次「游戏已可玩」的探测，不再每个模组各跑一份轮询；日志里只会出现一条 `游戏已就绪: 启动门等待 …`。
- **各自上限继续生效**：每个模组仍按自己的等待上限初始化，不会被等待时间最长的模组拖住。
- **兜底不卡死**：探测若提前结束（异常、主线程泵尚未就绪），等待中的模组会直接在自己的上限处继续初始化，不会停在启动门。
- **主线程识别自愈**：主线程 ID 只从 UniTask PlayerLoop 或帧泵线程确认；记录不正确时会自动更正，避免误把后台线程当主线程后出现调度延迟。
- **主线程调度自等待保护**：若等待排空的线程本身就是主线程，超过 100 ms 立即放弃并报告，不再等到超时让画面停住。

## 原生音频通道改为硬编码关闭

- 原生音频服务（UDP 端口 + `<audio>` 文件通道 + MCI 播放）改由加载器代码常量控制，当前固定关闭；`doorstop_config.json` 的 `audioControlEnabled` 仍会被读取与保留，但不再决定是否启动。
- 影响：**自定义音效 / BGM 替换不可用**（例如 AudioSkinMod 的音效方案）。游戏本体的音乐与音效不受影响。
- 加载器通过 `CESIUM_AUDIO_ENABLED` 告知 SDK 真实状态，并清理上一次运行遗留的 `port.txt` / `state.txt`，避免音效请求发往旧端口后静默丢失。
- 调试 Shell 中执行 `set audioControlEnabled true` 会提示该通道已在代码中关闭。

## 音频子系统开销

- 原生音频控制通道改为事件驱动（目录变更通知 + 兜底周期重读），空闲时不再持续打开请求文件；通知句柄创建失败的目录自动退回轮询读取。重复播放同一音效时复用已加载的 MCI 槽位。
- SDK 侧：未注册任何替换规则且没有事件订阅者时，声音事件直接放行；`configId → 事件名/事件 ID` 的结果做缓存；替换规则查询改为无锁读取；Unity 音频接口绑定日志只输出方法数量，不再拼接全部方法签名。

## 内置模组

- **角色半透明（CharacterTransparencyMod）**：按住热键时不再每帧遍历角色层级，只维持已修改过的渲染器透明度，降低持续按住时的开销。
- **星币商店助手（StarCoinShopMod）**：缓存 UI 管理器查询，并在面板关闭时释放，减少每帧重复查找。
