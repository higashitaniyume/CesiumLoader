# mod：FreeCameraMod（滚轮缩放）

> 源码：`src/FreeCameraMod/ModEntry.cs`。纯 SDK 用户，不使用任何反射或内部 API。
> **2.2.1 起整体重写**：旧版的「F1 开关俯瞰视角 / 滚轮调高度」已经删掉，这一页描述的是新行为。

## 1. 它做什么

| 时机 | 行为 |
| --- | --- |
| 进入游戏 / 进入棋盘 | **什么都不做**。相机完全是游戏自己的，没有开关、没有自动接管、不改任何相机参数 |
| 滚动鼠标滚轮 | **放大 / 缩小**：相机沿**当前视线方向**前后移动（向前滚 = 拉近），**朝向、俯角、滚转一点不变** |
| 按 `F1`（可改键） | **恢复原来的视角**：立刻回到游戏自己的机位，并把相机交还游戏 |

和旧版最本质的区别：旧版是「把相机抬到高处俯视」（视角一定会变），新版是「**同一个视角**只是拉近/拉远」——
所以看不到任何俯视/斜视的变化，画面不变形，只是远近变了。

## 2. 操作

| 操作 | 作用 |
| --- | --- |
| 滚轮向前 | 沿视线**拉近 / 放大**（每格 `zoomStep` 米） |
| 滚轮向后 | 沿视线**拉远 / 缩小**（看得更多） |
| `F1`（`restoreKey`） | 回到游戏原来的视角，相机交还游戏 |
| `F2`（`resetKey`） | 同上（第二个复原键；设成 `None` 可关掉） |

- **没有开关**：不需要先按什么键「进入自由相机」，滚一下就有；
- **不需要按 F1 才能退出**：把滚轮滚回原位（偏移回到 0）会自动交还相机，`F1` 只是「一下子回到原位」的快捷方式；
- **只「读」输入**：不 Capture 鼠标、不拦截按键。游戏自己的**鼠标拖拽平移 / 键盘平移照常有效**——
  缩放期间每帧都以「游戏本帧写下的位姿」为基准重算，所以可以一边拉远看全图，一边继续拖地图；
- `F1` 在**没缩放**的时候按下是空操作（不弹提示、不改任何东西）。

## 3. 配置

配置文件：`AstralParty_ModLoader\mods\FreeCameraMod\config.json`
（**与 mod 的 dll 同目录**；首次运行 / 从旧版升级时会自动生成，并**清掉旧版 v2.x 用过的键**）

```json
{
  "zoomStep": 20,
  "zoomInMax": 120,
  "zoomOutMax": 1500,
  "invertWheel": false,
  "smooth": true,
  "smoothTime": 0.12,
  "ensureFarClip": true,
  "requireReadyCamera": true,
  "maxReadyCameraHeight": 500,
  "notify": true,
  "restoreKey": "F1",
  "resetKey": "F2"
}
```

> ⚠️ 配置在 mod 初始化时**读一次**，改完需要**重启游戏**。
> ⚠️ 这个 JSON 解析器**不支持注释**（`//`）。写了注释会导致整份文件解析失败并被备份成
> `config.json.bak`，配置全部退回默认值。

| 字段 | 说明 |
| --- | --- |
| `zoomStep` | **每格滚轮**移动的米数（默认 20）。写坏（0 / 负数 / NaN）会退回默认值，不会变成「滚轮没反应」 |
| `zoomInMax` | 沿视线**向前**（放大）的最大米数（默认 120）。太大相机会穿进棋盘里 |
| `zoomOutMax` | 沿视线**向后**（缩小）的最大米数（默认 1500）。顶到极限后继续滚不会有任何变化 |
| `invertWheel` | 反转滚轮方向（默认 `false`：向前滚 = 拉近） |
| `smooth` / `smoothTime` | 平滑过渡（默认开，时间常数 0.12s）。关掉就是「一格一跳」、立刻到位 |
| `ensureFarClip` | 拉远时按需把 `farClip` 抬到 `原值 + 偏移`，免得远处棋盘被裁掉；结束时还原（默认 `true`） |
| `requireReadyCamera` | 菜单 / 加载过渡期不响应滚轮（默认 `true`）。否则在主菜单滚一下也会把过渡相机拉来拉去 |
| `maxReadyCameraHeight` | 占位相机判定用：朝向 `(0,0,0)` 且高度高于这个值（默认 500）就当成菜单/过渡相机 |
| `notify` | 是否弹「滚轮缩放中 / 已恢复」的屏幕提示（默认 `true`） |
| `restoreKey` | 复原键（默认 `F1`）。旧版的 `toggleKey` 会被继承过来 |
| `resetKey` | 第二个复原键（默认 `F2`）。`None` = 不用第二个键 |

## 4. 行为细节

- **只改位置，不改镜头**：mod 从不写相机的旋转，也不写 `FOV` / `nearClip`（`farClip` 只在
  `ensureFarClip=true` 且拉远到可能裁掉远处时才临时抬高，交还时还原）。
  所以「视角」这个词在这里是字面意思：朝向、俯角、滚转和游戏原来的一模一样。
- **缩放基准 = 游戏本帧写下的位姿**：每帧先读游戏写下的相机位姿，再在上面加「沿视线的前后偏移」。
  游戏自己在动（拖地图、跟角色、镜头过场）时偏移会跟着走，不会「锁死在一个点」。
  为了区分「相机里的值是我们写的」还是「游戏写的」，会比较当前位姿与上次写入值：完全一致 = 游戏这帧
  没动相机，就沿用上次识别出的基准（否则会在已经拉远的位置上再加一次偏移，越滚越远）。
- **偏移范围**：`[-zoomOutMax, +zoomInMax]`（正 = 向前/拉近）。顶到极限继续滚只返回原值，静默不刷提示。
- **自动交还**：偏移回到 0 且平滑收敛后（容差 0.25m）自动停止接管 —— 此刻相机里就是游戏自己的位姿，
  交还不会有任何跳变。
- **交还会写回一次位姿**：结束接管时会把「最后一次识别到的游戏位姿」写回相机一次，并还原 `farClip`。
  这样即使游戏那边（例如 Brain 失活、镜头不动的时候）不重写相机，也不会把我们算出来的缩放位姿留在相机上。
- **切场景 / 换相机**：一律清零偏移、结束接管，绝不把上一个场景的偏移套到新相机上。

## 5. 实现原理（为什么必须这么写）

本作实测（2026-09-20，国服）留下的两条硬约束，决定了实现方式：

1. **`CinemachineBrain` 在失活对象上**，靠 `VirtualCamera` 抢优先级不生效 —— 只有
   「每帧直接写主相机」可靠（详见 `docs/SDK-相机.md` §7）。
2. **游戏自己的相机逻辑每帧都在写相机**，所以我们的写入必须排在它后面：
   `UpdateService` 的 `OnLateUpdate` 实际时机是 `PostLateUpdate`，正好在游戏 `LateUpdate` /
   Cinemachine 之后、渲染之前 —— 本帧渲染用的就是缩放后的机位。

另外两条：

- **游戏完全没用滚轮**：反编译 `AstralParty.Runtime.dll` 里没有任何 `Mouse ScrollWheel` /
  `mouseScrollDelta` 的读取（游戏自己的平移是鼠标左键拖拽 + 键盘），所以滚轮是「白拿」的一个轴，
  不存在和游戏抢操作的问题，也不需要拦截输入（SDK 的 Capture 本来也拦不住游戏，见 `docs/SDK-输入与光标.md`）。
- **滚轮只可能来自 Unity 后端**：SDK 的 Win32 后端没有滚轮实现，`InputService.GetMouseScroll()`
  先读 `Input.mouseScrollDelta`（原生每格 ±1），取不到再回退 `Mouse ScrollWheel` 轴（默认每格 ±0.1，
  已折算成格数）。两个都拿不到就恒为 0，日志里会有「滚轮没反应」的排查线索。

## 6. 日志与自检

| 日志 | 含义 |
| --- | --- |
| `自由相机(滚轮缩放)已就绪: 滚轮上=拉近, 每格 20m …` | 初始化完成，打印实际生效的配置 |
| `滚动缩放: 开始接管相机(只改位置, 不动朝向/FOV) 进入前: …` | 第一次滚轮触发了接管 |
| `缩放校验(第60帧): 游戏位姿=(…) euler=(…) \| 偏移=…m 目标=…m 写入=(…) 实际=(…) 偏差=0m (写入生效)` | 写完立刻回读一致 = 写入生效；「游戏位姿」每帧在变 = 游戏自己的操作仍然有效 |
| `滚轮缩放: 已恢复原来的视角 (按键 F1), 偏移 -300m -> 0` | 按复原键交还 |
| `滚轮缩放: 偏移已回到原位, 自动交还相机` | 滚轮回位自动交还 |
| `滚轮缩放: farClip 已还原为 …` | 抬过 `farClip`，已按快照还原 |

`缩放校验` 只在接管的第 60 / 300 帧各记一次，不刷屏。

## 7. 排查

| 现象 | 先看什么 |
| --- | --- |
| 滚轮完全没反应 | 日志里有没有「滚轮缩放: 开始接管相机」；没有就是滚轮没读到（`INPUT` 日志 + 上面的「滚轮只可能来自 Unity 后端」）；如果日志是「当前是菜单/过渡相机」，说明还在菜单/加载里 |
| 有接管日志但画面不变 | 看 `缩放校验` 的「偏差」：> 0.5m 会额外打一条 `缩放位姿没写进相机`，说明这台相机拒绝外部写入 |
| 画面歪了 / 变成俯视 | 新版本不会写旋转。若出现，先确认 `AstralParty_ModLoader\mods\FreeCameraMod\` 下是 v2.2.1 的 dll + sidecar |
| 相机卡在缩放后的位置 | `F1` 复原；仍然卡住就看日志有没有「已恢复原来的视角」——若没有，多半是没读到按键（改键后确认键名拼写，写在配置里不受游戏改键影响） |
| 一滚就飞很远 | `zoomStep` 太大（例如把 20 写成 200）；`invertWheel` 只改方向不改步长 |

## 8. 与旧版（v2.x）的差异

| | v2.x（已废弃） | v2.2.1 |
| --- | --- | --- |
| 触发 | `F1` 开关（或 `autoActivate` 延迟自动进入） | 滚轮；进游戏不接管 |
| 视角 | 抬高到 `height` 米 + `pitch` 俯角（**视角会变**） | 沿视线前后移动（**视角不变**） |
| 配方键 | `mode/height/heightStep/pitch/fov/boardHeight/aimDistance/autoActivate/…` | `zoomStep/zoomInMax/zoomOutMax/invertWheel/smooth/…` |
| 退出 | `F1` 还原进入时的快照 | `F1`（或滚轮回原位）交还「游戏自己的位姿」，`farClip` 按快照还原 |

> 升级时旧键会在启动时自动删除并写入新的默认配置（只把旧版的 `toggleKey` 继承为 `restoreKey`），
> 不会被当成「配置损坏」备份成 `.bak`。
