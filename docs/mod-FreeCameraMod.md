# mod：FreeCameraMod（俯瞰视角）

> 源码：`src/FreeCameraMod/ModEntry.cs`。纯 SDK 用户，不使用任何反射或内部 API。

## 1. 它解决什么

本作是棋盘类游戏，默认相机机位很低、需要拖动鼠标才能看全地图。这个 mod 提供两种俯瞰方式：

| 模式 | 视角 | 游戏自己的鼠标/键盘操作 |
| --- | --- | --- |
| `raise`（**跟随抬高，默认**） | 抬高到 `height` 俯视，**朝向与瞄准点跟着游戏走** | **照常可用**（转视角、平移都还能看出效果） |
| `preset`（固定俯瞰） | 相机被每帧钉死在配置好的位姿 | ⚠️ **会失效** —— 游戏每帧写下的相机位姿都被覆盖，实测就是"开着动不了、关掉才恢复" |

> 想边看高处边正常玩，用默认的 `raise`；只想固定一个机位（例如截图/观察）再用 `preset`。

## 2. 配置

配置文件：`AstralParty_ModLoader\mods\FreeCameraMod\config.json`
（**与 mod 的 dll 同目录** —— SDK 的 `ModConfig` 就按这个位置读写，Toys 的配置表单也写这里）

```json
{
  "mode": "raise",
  "height": 160,
  "heightStep": 10,
  "pitch": 70,
  "fov": 80,
  "boardHeight": 0,
  "aimDistance": 0,
  "maxTargetDistance": 500,
  "maxReadyCameraHeight": 500,
  "autoActivate": true,
  "autoActivateDelay": 15,
  "orbitDistance": 12,
  "distanceStep": 1.5,
  "speed": 20,
  "rotationSpeed": 2,
  "nearClip": 0.05,
  "farClip": 2000,
  "invertY": false,
  "lockCursor": false,
  "toggleKey": "F1",
  "resetKey": "F2"
}
```

> ⚠️ 配置在 mod 初始化时**读一次**，改完需要**重启游戏**。
> ⚠️ 这个 JSON 解析器**不支持注释**（`//`）。写了注释会导致整份文件解析失败并被备份成
> `config.json.bak`，配置全部退回默认值。

### 关键字段

| 字段 | 说明 |
| --- | --- |
| `mode` | `raise`（跟随抬高，默认）/ `preset`（固定俯瞰）/ `orbit`（绕点旋转）/ `fly`（自由飞行）；`follow`、`offset` 是 `raise` 的别名 |
| `height` | **相机绝对高度**（世界单位）。越大看得越广。160 大约能覆盖整张棋盘 |
| `pitch` | 俯视角度。70° 接近垂直俯视；45° 更斜、更有立体感 |
| `fov` | 视野角。80 比游戏默认的 45 更广，配合高度能装下整张地图 |
| `boardHeight` | 棋盘所在平面的 Y 高度，用于计算"相机该往后退多少" |
| `aimDistance` | 瞄准点相对相机正前方的偏移。>0 时瞄准点更远，视角更平；0 = 沿用游戏当前的瞄准点 |
| `maxTargetDistance` | 自动找瞄准点时允许的最大搜索半径；调大后可以看更远 |
| `maxReadyCameraHeight` | 高于这个高度、且朝向为 (0,0,0) 的相机视为"菜单/过渡相机"，**拒绝接管**（默认 500） |
| `heightStep` | 游戏内用 `Ctrl+=` / `Ctrl+-` 调高度时每次的米数（默认 10） |
| `autoActivate` | 启动后自动进入俯瞰视角（默认 true） |
| `autoActivateDelay` | 进入前的等待秒数（默认 15）。菜单/加载阶段的相机还没就绪，太早接管会闪 |
| `nearClip` / `farClip` | 裁剪面。`farClip` 必须够大（2000），否则远处棋盘会被裁掉 |
| `toggleKey` | 开关热键，**默认也只有 F1** |
| `resetKey` | 恢复默认视角（F2；`raise`/`preset` 下无实际作用，键位仍会写入配置） |

## 3. 热键

俯瞰类模式（`preset` / `raise`）只绑这几个键，**完全不接管鼠标**（`lockCursor` 对俯瞰模式无效）：

| 热键 | 作用 |
| --- | --- |
| `F1` | 开关（`toggleKey` 可改） |
| `Ctrl` + `=`（也就是 `+`，小键盘 `+` 也行） | **抬高相机**，每按一次 `heightStep` 米 |
| `Ctrl` + `-`（小键盘 `-` 也行） | **降低相机**，每按一次 `heightStep` 米 |

高度热键的几个要点：

- **立刻生效，不用重启游戏**：`raise` 模式每帧都按 `height` 重算位姿，`preset` 模式在按键时重算一次；
- **只"读"键盘，不抢输入**：不接管鼠标、不拦截游戏自己的按键，所以不会出现"视角被 mod 抢走"；
- **会自动记下来**：停手约 1.2 秒后写回 `config.json`（退出接管时也会补写一次），下次启动继续用这个高度；
- 高度范围限制在 **5 ~ 2000 米**，到极限时只弹提示、不再变化；
- 屏幕上会弹出当前高度（如 `自由相机: 高度 180m`），日志里对应 `高度调整: 160m -> 170m (步进 10m)`。

## 4. 自动进入与就绪校验

1. 启动后每 30 帧检查一次；
2. 未到 `autoActivateDelay` 秒 → 继续等；
3. **就绪校验不通过** → 继续等，并记录一次（只记一次，避免刷屏）：
   - 相机是占位/过渡相机（朝向 (0,0,0) 且位于原点或高于 `maxReadyCameraHeight`）；
   - 算出的瞄准距离顶到 `maxTargetDistance` 上限（相机根本没在看棋盘）。
   日志形如 `自动进入推迟: 主相机尚未就绪(…), 等进入棋盘后再接管`；
4. 就绪 → 记录 `自动进入跟随抬高视角`，保存 `CameraState` 快照后接管。

手动按 F1 时同样会做这套校验；不通过就只提示 `相机未就绪 (…)` 并**不接管**，
避免把菜单/过渡期的坏位姿记进快照（退出时再还原回去就是"画面变黑、HUD 还在"）。

## 5. 接管方式与可观测性

- **接管**：每帧在 `PlayerLoopTiming.PostLateUpdate` 写入相机位姿/镜头参数。
  选这个时机是因为它排在游戏的 `LateUpdate` / Cinemachine 之后，写入不会被覆盖。
- **不接管时**：完全不碰相机，游戏一切如常。
- **退出时**：把进入前保存的 `CameraState` 写回（位姿/镜头参数）。
  **不还原 `enabled`** —— 快照可能采自过渡期的失活相机，把 `enabled=false` 还原回去
  会让画面整个变黑（HUD 还在、声音照旧）。详见 `CameraState.Restore` 的说明。

日志里能看到两种校验（排查"看起来没生效"时先看这个）：

| 日志 | 含义 |
| --- | --- |
| `接管校验(第60帧): 写入后实际 pos=… 偏差=0m (写入生效)` | `preset`：写回后读回来一致 → 确实生效 |
| `帧首校验(第60帧): … -> 上一帧渲染用的就是预设视角(生效)` | `preset`：下一帧开头读取上一帧结果，确认没被游戏覆盖 |
| `跟随校验(第60帧): 游戏位姿=… -> 抬高后=… 偏差=0m (写入生效)` | `raise`：确认基准来自游戏、且写入生效；基准每帧都在变 = 游戏自己的操作有效 |

## 6. 俯瞰几何（preset 与 raise 共用）

相机位置由高度和俯角推出（见 `ApplyOverheadGeometry`）：

```
target = 基准相机朝向射线 ∩ 高度为 boardHeight 的平面   // 或 aimDistance 指定的点
back   = (height - target.y) / tan(pitch)              // 水平后退距离
camera = target - horizontalForward(yaw) * back         // 相机世界坐标
rotation = Euler(pitch, yaw, 0)
```

区别只在"基准"：

- `preset`：基准 = 进入时的相机（位姿固定不变）；
- `raise`：基准 = **游戏本帧写下的相机位姿**（每帧重取），所以 `yaw` 和瞄准点都跟着游戏走。

> `raise` 每帧判断"游戏这帧有没有动相机"：若当前位姿与我们上一帧写入的完全一致，
> 就沿用上次识别出的基准 —— 否则在静态场景里会把偏移反复叠加，相机越飞越高。

`height` 是**绝对高度**（不是相对棋盘的偏移），所以调高度时不用担心棋盘在哪一层。

## 7. orbit / fly 模式（保留但默认不用）

- `orbit`：绕观察点旋转。**鼠标转向在本作里不可靠**——游戏自己每帧重写相机输入状态，
  SDK 的鼠标轴读取拿不到有效增量。需要严格可控的自动环绕时可用键盘/代码驱动。
- `fly`：无重力自由飞行，主要用于调试。

两者都保留实现（可继续维护），但日常用 `raise`。
