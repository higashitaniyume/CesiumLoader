# 卡面动画性能优化（2026-10-13）

本次修改依据本地 ETW 记录：静态场景游戏帧提交约 118 FPS，动态场景约 13 FPS；同一游戏线程单核采样接近 100%，动画 PNG 每秒重复读取约 115 次，GPU 3D 利用率显著下降。旧 128 MiB 逐帧 LRU 缓存只容纳约 103 个 404×400 帧，而现场 10 套动画共 674 帧，循环播放持续回到同步解码路径。

## 播放与缓存

- 按 `动画 manifest + 资源名` 建立序列。不同资源名仍单独缓存，符合 FairyGUI 对 nativeTexture.name 与 loader.url 的校验。
- 缓存准入预留整套动画的像素容量，优先可完整容纳的小动画；没有逐次载入逐帧全局 LRU 淘汰。
- 默认预算 512 MiB，可在 CardSkinMod 的 config.json 添加 `"AnimationCacheMiB": 512` 调整；取值限制 64–1024。部署不重写已有配置。
- 依据实际 Texture2D.isReadable 核算每像素 4 或 8 字节，并对 mipmap 保守留额；后续回退产生更大占用会提高预留。
- 无法完整容纳的序列使用当前帧、上一帧、准备帧周转。预算为估算像素容量，不包含静态图片、包装/材质对象、Unity 延迟销毁等所有内存。
- 所有可见卡面先登记需求，然后每个引擎 frameCount 最多解码一张新图。完整序列在当前需求满足后轮流预热其余帧。首次显示暂时保留封面/原生视频，或显示已经准备好的帧。
- PNG 解码和 Unity 纹理创建仍在游戏线程上执行；这里是分帧调度，不是工作线程调用 Unity API。预热完成后预算内序列直接复用纹理。
- 不再显示的序列 2 秒后清理，重新打开可能需要预热。

## UI 与生命周期

- 全树发现最多约 10 次/秒，手牌变更使下一次发现立即执行。
- 每个游戏帧只检查已登记的可见动画卡。按动画帧时钟取缓存；未变帧/未换纹理时跳过布局和 GLoader 加载操作。
- 避免对图鉴滚动区不可见卡面进行动画预热，检查父控件可见性、group、onStage 及 IsChildInView。
- 快速路径检查正面/完整卡面 URL 和激活的 VideoKey；组件池复用或资源改变会撤销旧登记。
- 回收只重置仍属于当前绑定的 Mod 纹理，不清空复用后游戏刚设置的另一张卡面。
- 永久解码失败与等待预热区分，失败会撤销登记并回退。
- 配表只有对象替换/初次就绪时重建映射；静态封面不再覆盖有效动画缓存。

## 验证状态

Release 构建作为编译兼容性检查；按用户要求不运行测试。实际 FPS 改善和热更环境 API 兼容性由用户游戏内验证。不得仅凭构建或离线源代码审查宣称帧率已恢复。

建议在相同图鉴界面等待预热后重录 ETW，比较 PNG 重读次数、读取线程单核占用和游戏帧提交率。缓存外序列仍可能重复解码；增加预算只能改善容量压力，不能消除首次解码或全部 UI CPU 工作。
